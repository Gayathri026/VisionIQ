Abstract—Vision-language applications often execute a fixed
collection of computer-vision operations regardless of the ques-
tion being asked. Such static pipelines can waste computation,
increase response time, and return evidence that is irrelevant
to the user’s intent. This paper presents VisionIQ, an adap-
tive, query-aware multi-agent vision intelligence framework that
selects and coordinates specialised vision agents according to
the semantic requirements and estimated execution cost of a
natural-language query. The system integrates a React and Vite
interface, a FastAPI backend, LangGraph-based orchestration,
YOLOv11 object detection, EasyOCR text extraction, OpenCV-
based heuristic anomaly analysis, scene understanding, retrieval-
augmented grounding, root-cause analysis, and recommendation
generation. A deterministic fallback supports routing when
language-model intent classification is unavailable or uncertain.
Agent outputs are consolidated into an evidence-oriented re-
sponse, while SQLite and SQLAlchemy persist query history
and execution traces. The planner represents agent utility as a
weighted function of query relevance, evidence capability, com-
putational cost, and expected latency. This paper describes the
architecture, mathematical routing formulation, implementation,
failure-handling strategy, and a reproducible evaluation protocol.
Quantitative performance claims are not reported as measured
results because benchmark logs and repeatable test outputs
have not been supplied for this manuscript. The contribution
is therefore presented as an implemented systems design and
an evaluation-ready methodology. Measured claims should be
added only after the evaluation protocol has been executed and
documented.

I. INTRODUCTION
Computer-vision systems are increasingly expected to an-
swer questions expressed in natural language rather than
expose a separate interface for every visual task. A user
may ask how many objects appear in an image, what text is
visible on a label, whether a scene contains a possible defect,or what action should be considered next. These questions
require different combinations of visual perception, text extrac-
tion, contextual interpretation, and reasoning. Running every
available model for every request can introduce unnecessary
computation and make it harder to identify which evidence
supports the final answer.
VisionIQ addresses this problem through query-aware, cost-
aware orchestration. Instead of treating a visual request as
one monolithic model call, the system interprets the query,
estimates which specialist agents are useful, invokes a se-
lected subset, and consolidates their outputs into a grounded
response.
The implemented application combines a React 18 and Vite
frontend, FastAPI backend, LangGraph workflow orchestra-
tion, YOLOv11 object detection, EasyOCR, OpenCV-based
heuristic anomaly analysis, scene understanding, retrieval-
augmented generation (RAG), root-cause analysis (RCA),
recommendation generation, and SQLite/SQLAlchemy persis-
tence. CPU/CUDA execution fallback and agent-level error
handling support practical execution across different runtime
conditions.
The principal contributions are:
•A query-aware orchestration design that maps natural-
language intent to a selective set of specialist visual
agents.
•A cost-aware routing formulation that balances query
relevance and evidence capability against estimated ex-
ecution cost and latency.
•An evidence-consolidation workflow connecting visual
findings with retrieval-grounded context, RCA, and rec-
ommendations.
•A web application architecture supporting query history,
execution traces, annotated outputs, fallback routing, and
fault isolation.
•A reproducible evaluation protocol covering perception
quality, routing quality, latency, agent utilisation, and
failure recovery.
II. RELATEDWORK ANDRESEARCHGAP
A. Visual Perception
Object detection identifies and localises objects in images.
The YOLO family popularised single-stage object detec-
tion, providing a foundation for real-time applications [6].
Transformer-based detection approaches such as DETR offer
a different formulation of the detection problem [7]. VisionIQ
uses YOLOv11 as a specialist detector rather than treating it
as a complete solution to every visual question.
Optical character recognition extracts text from visual in-
puts. EasyOCR provides a reusable implementation for text
extraction across multiple scripts and languages [2]. OpenCV
provides image-processing operations that can support edge
analysis, blur estimation, and other visual heuristics [3]. The
quality of the output depends on the input, configuration, and
intended task.
B. Deep Learning and Visual Understanding
Deep residual networks introduced residual learning for
training deeper neural networks [9]. U-Net demonstrated an
encoder-decoder design with skip connections for image seg-
mentation [8]. Large annotated image collections such as
COCO have helped establish common evaluation practices
for object detection and scene understanding [10]. These
methods provide relevant background for the visual perception
capabilities used in modern intelligent applications.
C. Agent Orchestration and Grounded Reasoning
Graph-based orchestration supports conditional branches,
shared state, and recovery paths. VisionIQ uses LangGraph
to represent transitions between intent classification, agent
selection, execution, and response synthesis.
The ReAct approach combines reasoning and actions in
language-model workflows [11]. Toolformer investigates how
language models can learn to use external tools [12], while
the MRKL architecture explores modular combinations of
language models and external reasoning components [13].
Retrieval-augmented generation combines generative mod-
els with retrieved external knowledge [4]. Subsequent sur-
veys have examined RAG architectures and their evaluation
challenges [14]. In VisionIQ, retrieval supplies contextual
information; it does not independently prove the correctness
of visual observations.
D. Research Gap
A fixed pipeline executes the same modules for requests
with different requirements. A detector-only design is insuf-
ficient for text-centric questions, while an OCR-only path
cannot provide complete object localisation. Running every
available component can increase computational work unnec-
essarily.VisionIQ focuses on the orchestration layer: it esti-
mates task-agent compatibility, conditionally executes relevant
agents, preserves their outputs as evidence, and handles partial
failures. The intended contribution is the integration of query-
conditioned selection, cost-aware planning, evidence aggrega-
tion, and persistent traceability rather than a claim that the
underlying detection or OCR models are novel.
III. SYSTEMARCHITECTURE
Figure 1 presents the proposed VisionIQ processing archi-
tecture. A request enters through the frontend, is validated by
the backend, and proceeds to intent classification and cost-
aware planning. Selected agents produce intermediate results
that are consolidated before response generation.
A. Request and Intent Interpretation
The frontend submits a visual input and a natural-language
question to the FastAPI backend. The backend validates the
request and creates a shared execution state containing the
query, input references, intent labels, selected agents, agent
outputs, error information, and final response.
An LLM-based classifier estimates the request intent. A
deterministic fallback maps recognisable query patterns to a
conservative agent set when classification fails or produces an
unusable result. Ambiguous queries may still require clarifi-
cation or a broader selection.
B. Specialist Vision Agents
The implemented system contains the following agent ca-
pabilities:
•Object Detection Agent:Uses YOLOv11 to identify ob-
jects and return labels, confidence values, and bounding-
box coordinates.
•OCR Agent:Uses EasyOCR to extract visible text
from labels, documents, signs, and other supported visual
inputs.
•Defect Detection Agent:Uses OpenCV-based heuristics,
including blur and edge analysis, to identify candidate
visual irregularities. These cues are not equivalent to a
validated industrial defect classifier.
•Scene Understanding Agent:Provides contextual inter-
pretation for questions requiring a broader description
than individual object detections.
•RAG Component:Retrieves relevant documentation or
knowledge snippets when suitable contextual information
is available.
•RCA and Recommendation Components:Combine
available evidence to propose possible explanations and
suggested next steps. Causal claims must remain qualified
when the evidence is insufficient.
C. Execution and Persistence
LangGraph coordinates conditional branches using shared
state. The orchestration layer records outputs and errors from
individual agents. If one agent fails, successful branches may
still provide a partial response.

IV. COST-AWAREDYNAMICAGENTSELECTION
Letqdenote a user query andA={a 1, a2, . . . , a M}denote
the set of available agents.
For each agenta, the planner estimates:
•R(a, q): relevance of agentato queryq.
•E(a): expected evidence capability.
•C(a): normalised computational cost.
•L(a): normalised expected latency.
The routing score is defined as
S(a, q) =αR(a, q) +δE(a)−βC(a)−γL(a)(1)
The configured weights are
α= 0.50, β= 0.20, γ= 0.15, δ= 0.15.(2)
Relevance and evidence capability increase the score, while
estimated cost and latency reduce it. These weights are engi-
neering parameters and require empirical calibration.
An agent is eligible for execution when its score reaches
the configured thresholdτ= 0.50:
Aq={a∈ A:S(a, q)≥τ}.(3)
The selected set may be expanded when a query requires
complementary evidence. For example, a request to read a
label attached to an object may require both object detectionand OCR. Mandatory dependencies and fallback rules should
take precedence over an overly restrictive threshold.

The retention of uploaded images and traces should follow

vision agents from the quality of the orchestration strategy.
Correct detection does not independently demonstrate correct
routing, and a fluent answer does not prove that its claims are
supported by the input image.

B. Evaluation Metrics
Detection quality can be measured using precision, recall,
and mean average precision at explicitly defined IoU thresh-
olds. OCR quality can be assessed using character error rate
(CER) and word error rate (WER).
Routing quality should be evaluated using agent-set pre-
cision, recall, and F1 against annotated required-agent sets.
End-to-end answers should be scored for task correctness
and evidence support using a documented rubric and, where
possible, blinded human review.
Efficiency measurements should include end-to-end latency,
number of agents invoked per query, model calls, and peak
memory or compute consumption where measurable. Reliabil-
ity measurements should include successful completion rate,
fallback activation rate, and graceful-degradation rate under
injected agent failures.

VI. DISCUSSION, LIMITATIONS,ANDRESPONSIBLEUSE
VisionIQ treats orchestration as a first-class component.
A user question determines which capabilities are relevant,
and the selected agents produce intermediate evidence before
synthesis. Persistent traces can help diagnose incorrect routing,
failed model execution, and unsupported recommendations.
Several limitations remain. First, relevance, evidence, cost,
and latency estimates require calibration against representative
queries. The configured weights and threshold are not univer-
sally optimal.
Second, OpenCV-based anomaly cues are heuristic and
should not be presented as validated defect diagnoses without
domain-specific labelled data. Third, errors in object detection
or OCR may propagate into downstream reasoning. Fourth,
retrieval can return irrelevant or incomplete material, and
generated explanations may overstate the available evidence.
Fifth, latency depends on hardware, model warm-up, image
resolution, concurrency, and software versions. Generalisation
therefore requires explicit reporting of the experimental envi-
ronment.
Responsible deployment should distinguish observations
from inferred explanations. The system should communicate
uncertainty, avoid claiming root causes without sufficient ev-
idence, and recommend human inspection for safety-critical
decisions. Stored images and traces should be protected by
access controls and appropriate retention policies.
VII. CONCLUSION ANDFUTUREWORK
This paper presented VisionIQ, an adaptive multi-agent
vision intelligence framework that combines query-aware
routing with specialised visual analysis, retrieval-grounded
context, evidence aggregation, and response synthesis. Its
application architecture integrates React/Vite, FastAPI, Lang-
Graph, YOLOv11, EasyOCR, OpenCV heuristics, RAG,
RCA, recommendations, SQLite/SQLAlchemy persistence,
and CPU/CUDA fallback with agent-level error handling.
The routing formulation balances query relevance and ev-
idence capability against estimated computational cost and
latency. The graph-based workflow supports conditional ex-
ecution and partial recovery when an agent fails.
This manuscript documents the system design and defines
an evaluation protocol. It does not claim a measured accuracy
or latency improvement without benchmark outputs. Futurework includes calibrated routing scores, improved agent-
cost estimation, explicit evidence provenance, domain-specific
anomaly evaluation, and evaluation across images and video
streams.
